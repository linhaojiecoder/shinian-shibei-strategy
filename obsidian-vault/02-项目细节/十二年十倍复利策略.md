## 四、★ 数据口径（本项目最重要的结论，反复踩坑）

### 根因
westock 数据源的复权功能是坏的：
- 默认 `--fq` 不传 = 前复权 qfq（把份额拆分跳空抹平）
- `--fq nofq` = 跨拆分日口径错乱
- `--fq bfq` = 直接报错

### 解法
绕过 westock，用腾讯原始接口 `web.ifzq.gtimg.cn/appstock/app/kline/kline`（第 6 参数留空 = 真正不复权），拆分跳空 + 分红除息跳空都完整保留。

### 已验证的事件表（权威公告核实）

| 标的 | 除权事件 | 日期 |
|---|---|---|
| 沪深300 510300 | 现金分红约13次 | 2014起每年 |
| 纳指 513100 | **1:5 份额拆分** | 2022-01-13 |
| 标普500 513500 | **1:2 份额拆分**（无分红） | 2022-03-29 |
| 黄金 518880 | 1:0.3776 折算（上市前） | 2013-07-24 |
| 创业板 159915 | 通常无 | — |

### 回测脚本必须正确处理的三件事
1. 成交用「真正不复权价」（不碰任何复权口径）；
2. 份额拆分「锚定到拆分后首个交易日」同步调整持仓份额（拆分日停牌，不能按公告日匹配，否则份额不调整、市值凭空缩水）；
3. 区分两套分红假设（分红再投入 vs 分红现金入账）。

### 独立交叉验证（买入持有收益）
- 纳指 856.4%、标普 428%、沪深300 112.2%、创业板 103%、黄金 28.6%，全部符合公开常识。

## 五、版本演进与踩坑记录

### 关键踩坑（按时间倒序）

1. **westock 复权功能损坏**（2026-10-27）：bfq=nofq=qfq 混乱，改用腾讯原始接口。
2. **标普拆分比例记错**：曾记成 1:5，实际是 **1:2**。
3. **份额拆分停牌日不匹配 bug**：拆分日停牌不在交易日序列，`e.date==d` 永远匹配不到，导致份额不调整。
4. **fetchRealtime 代码格式 bug**：传纯代码 `510300` 而非 qt 代码 `sh510300`，导致盘中实时刷新从未生效。
5. **成本还原漏掉"减仓"动作**：if/else 都没命中"减仓"，导致成本被摊薄（纳指成本 1.9255 vs 正确 2.275）。
6. **净值断崖 bug**：currentNav 除以 st.capital（3423万）而非起步本金 300 万，导致新滚净值≈1.0。
7. **Electron file:// 下 fetch CORS 拦截**：data.json 必须走 IPC（ipcMain.handle('get-data')）。
8. **electron-builder 被沙箱拦截**：改用 ditto 手动组装 .app。

### 版本里程碑
- v1.0 → v2.0：修前视偏差、改真实成交
- v3.0 → v3.4.0：UI 改版（同花顺式）、模块拆分、数据口径彻底修复

完整逐日记录见 [[../03-每日沟通日志/2026-10-27]] 及工作记忆 `.workbuddy/memory/`。

## 六、如何复现

```bash
# 1. 拉真正不复权价（腾讯原始接口，无需账号）
python3 rebuild_true_nofq.py
# 2. 跑回测
python3 sim_v4.py
# 3. 生成 App 用 data.json
python3 gen_data_full.py
# 4. 运行/打包 App
cd app_1.0 && npm install && npm start   # 运行
cd app_1.0 && bash build_mac.sh          # 打包 dmg
```
