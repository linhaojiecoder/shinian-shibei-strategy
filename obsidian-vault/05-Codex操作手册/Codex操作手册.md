# Codex 操作手册

> 本手册定义 Codex 如何使用和维护这个知识库（Obsidian vault）。

---

## 一、知识库定位

这是 Codex 的**跨项目永久记忆**。存放：
1. 用户长期偏好与决策习惯（[[../00-偏好与决策习惯/用户偏好与决策习惯]]）
2. 全部项目索引与细节（[[../01-项目索引/README]]、[[../02-项目细节/README]]）
3. 每日沟通日志、每周复盘沉淀

物理位置：GitHub 私有仓库 `linhaojiecoder/shinian-shibei-strategy` 的 `obsidian-vault/` 目录，通过 git 同步。

---

## 二、日常工作流（三条铁律）

### 铁律 1：任务前按需读取

每次接到新任务，**先读**：
1. `00-偏好与决策习惯/用户偏好与决策习惯.md`（必读，决定回复风格）
2. 与本任务相关的 `01-项目索引` 和 `02-项目细节` 中的文档

**原则**：按需读取，不盲目全读。先看索引判断哪个项目相关，再深入读对应细节。

### 铁律 2：每晚 10 点整理当日记录

每天 22:00，把当日所有沟通记录整理进 `03-每日沟通日志/YYYY-MM-DD.md`：
- 当日做了什么、聊了什么、产出什么
- 更新相关项目的状态（版本号、关键数据、待办）
- 记录新踩的坑、新确定的偏好

模板见 [[../03-每日沟通日志/README]]。

### 铁律 3：每周复盘沉淀

每周日，做一次复盘：
- 把本周零散的每日日志，沉淀成结构化的项目细节更新
- 清理冗余（重复信息、已过时的状态）
- 更新项目索引的状态标记
- 产出当周复盘笔记到 `04-每周复盘/YYYY-WW.md`

---

## 三、文件组织规范

| 目录 | 命名规则 | 说明 |
|---|---|---|
| 03-每日沟通日志 | `YYYY-MM-DD.md` | 一天一个文件 |
| 04-每周复盘 | `YYYY-WW.md`（如 2026-W44） | 一周一个文件 |
| 02-项目细节 | 项目名.md | 一个项目一个文件 |

---

## 四、同步方式

- 所有改动完成后，`git add` + `git commit` + `git push`，保持知识库与 GitHub 同步。
- 这样 Codex 换任何机器、任何环境，`git pull` 即可拿到最新记忆。

---

## 五、写作风格约束

1. 简体中文。
2. 结构化：多用表格、标题、列表，便于快速检索。
3. 结论前置：先给结论，再展开细节。
4. 记录「踩坑」时，写清楚「现象 → 根因 → 解法」三段式。
